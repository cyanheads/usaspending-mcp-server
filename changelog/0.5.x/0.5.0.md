# 0.5.0 — 2026-10-12

## Added

- **`psc_codes`, `def_codes`, and `assistance_listings`** filter the `filters` of `usaspending_spending_by_geography`, `usaspending_spending_by_category`, and `usaspending_spending_over_time`, and `usaspending_search_awards` takes all three both flat and inside its `filters` (it took only a flat `assistance_listings` before), each echoed as `applied_*` ([#77](https://github.com/cyanheads/usaspending-mcp-server/issues/77)). PSC and DEF codes are sent uppercased; `assistance_listings` with only contract or IDV award types fails as `assistance_listings_type_mismatch`, `psc_codes` with only assistance types as `psc_codes_type_mismatch`.
- **`usaspending_spending_by_geography` `shape_codes`** (1–500, beside `limit`) returns only the listed areas, reaching counties ranked past `limit`; the codes echo as `applied_shape_codes` and an unmatched code is named in the `notice` ([#72](https://github.com/cyanheads/usaspending-mcp-server/issues/72)).
- **`usaspending_get_award` `assistance_listings[]`** (`number`, `title`, `obligation`), `recipient.parent_uei`, `recipient.parent_recipient_id`, `recipient.business_categories`, and `total_loan_value` / `total_subsidy_cost` on loans; `recipient.uei` and the three-letter `country_code` on `recipient.location` and `place_of_performance` are now populated ([#68](https://github.com/cyanheads/usaspending-mcp-server/issues/68)).
- **`usaspending_get_recipient` `period`** names the totals window, `FY<year>` or `trailing 12 months` ([#67](https://github.com/cyanheads/usaspending-mcp-server/issues/67)).
- **`usaspending_get_agency` `sub_agency_fiscal_year`** and an optional **`unavailable_sections`** listing each failed section with its `reason` ([#86](https://github.com/cyanheads/usaspending-mcp-server/issues/86), [#69](https://github.com/cyanheads/usaspending-mcp-server/issues/69)).
- **`usaspending_spending_by_category`** `recipient_duns` rows carry `recipient_id` and `uei` when upstream has them ([#83](https://github.com/cyanheads/usaspending-mcp-server/issues/83)).
- **`invalid_location`** (`usaspending_search_awards`), **`psc_codes_type_mismatch`** (`usaspending_search_awards` and the three spending analytics tools), and **`conflicting_input`** (`usaspending_get_agency`) typed failures; `assistance_listings_type_mismatch`, until now on `usaspending_search_awards` alone, is added to the three spending analytics tools.

## Changed

- **BREAKING: unknown keys inside the nested `filters`, `time_period`, and `location_filter` objects are rejected** with the key path named (for example `time_period.fiscal_year`); they were dropped and the call ran without them ([#74](https://github.com/cyanheads/usaspending-mcp-server/issues/74)). `usaspending_search_awards` rejects `filters.recipient_id`.
- **BREAKING: `usaspending_autocomplete_filters` agency rows drop `id`** and carry the matched agency's own `name` (the top-tier parent was returned for a sub-agency), with `abbreviation`, `tier`, and the parent in `toptier_name` / `toptier_code`; `code` is no longer advertised for agencies ([#71](https://github.com/cyanheads/usaspending-mcp-server/issues/71)).
- **BREAKING: `usaspending_get_agency` rejects any call with both `toptier_code` and `agency_slug`** as `conflicting_input`, a matching pair included ([#75](https://github.com/cyanheads/usaspending-mcp-server/issues/75)).
- **`usaspending_search_awards` `location_filter` is normalized** (`country` defaults to `USA`, a territory code becomes `USA` plus its state, a 2-digit FIPS `state` becomes its postal code, a 5-digit county FIPS stands alone) and echoed as `applied_location`. A malformed `country`, `state`, or `county` fails as `-32602`; an unknown US state, a county without a state or with an armed-forces state (`AA`/`AE`/`AP`), a county or FIPS-number state under a non-USA country, and parts that name different states fail as `invalid_location` ([#70](https://github.com/cyanheads/usaspending-mcp-server/issues/70)).
- **`usaspending_get_recipient` totals** cover the requested `fiscal_year` instead of always the trailing 12 months ([#67](https://github.com/cyanheads/usaspending-mcp-server/issues/67)).
- **`usaspending_get_agency`** reports the most recent fiscal year with budget data, and `sub_agencies` cover that same year ([#81](https://github.com/cyanheads/usaspending-mcp-server/issues/81), [#86](https://github.com/cyanheads/usaspending-mcp-server/issues/86)). A failed budget or sub-agency request omits those fields, and `sub_agency_page` / `has_more_sub_agencies` become optional ([#69](https://github.com/cyanheads/usaspending-mcp-server/issues/69)).
- **`truncated` / `shown` / `cap` are set only on evidence** (an upstream `hasNext`, or a row received past `limit`) in `usaspending_autocomplete_filters`, `usaspending_search_awards`, and `usaspending_get_idv_awards`, where any full page set them before; a page that exactly fills `limit` is no longer labeled truncated, and the two paged tools still report `has_next`. Autocomplete at `limit: 500`, the upstream maximum, says in its new `notice` that more matches may exist ([#76](https://github.com/cyanheads/usaspending-mcp-server/issues/76)).
- **`usaspending_disaster_spending` geography** returns a page of `limit` areas (default 10) with `total` counting every area and `has_next` set from the page position ([#73](https://github.com/cyanheads/usaspending-mcp-server/issues/73)).
- **Request timeouts:** `USASPENDING_TIMEOUT_MS` defaults to 45000 (was 30000) and `USASPENDING_RETRY_BUDGET_MS` to 45000, or the timeout when higher (was 1.5 × the timeout). A timed-out attempt is not retried; 5xx and network failures still retry inside the budget ([#79](https://github.com/cyanheads/usaspending-mcp-server/issues/79)).
- **Framework (mcp-ts-core 0.13.15):** unknown nested keys are rejected with the key path named (the mechanism behind #74); `{"keyword": null}` and a lone string for an array filter such as `filters.keywords: "water"`, rejected with `-32602` before, are repaired and accepted.
- **Docker, `.mcpbignore`, docs:** the base image is Bun 1.4.3; the `.mcpb` bundle excludes `tests/`, `src/`, `scripts/`, `docs/`, `coverage/`, `.github/`, and `.vscode/` ([#88](https://github.com/cyanheads/usaspending-mcp-server/issues/88)); `framework-skills/` is synced to 0.13.15.

## Removed

- **BREAKING: `usaspending_spending_by_category` `category: "recipient_parent_duns"`**; it always answered 404 upstream ([#80](https://github.com/cyanheads/usaspending-mcp-server/issues/80)).
- **BREAKING: `usaspending_get_recipient` `award_type`**; the endpoint has no award-type selector, so the value was ignored. Use `usaspending_spending_over_time` with `filters.recipient_id` and `award_type_codes` for totals by type ([#67](https://github.com/cyanheads/usaspending-mcp-server/issues/67)).
- **`usaspending_get_award` `cfda` and `recipient.business_types`**, never populated; replaced by `assistance_listings[]` and `recipient.business_categories`. An empty `place_of_performance` or `recipient.location` is omitted instead of returned as `{}` ([#68](https://github.com/cyanheads/usaspending-mcp-server/issues/68)).
- **`usaspending_spending_by_geography` `award_count`** (result field and "Awards" column), never populated ([#82](https://github.com/cyanheads/usaspending-mcp-server/issues/82)).

## Fixed

- **An Assistance Listing or PSC filter the award types cannot match** — `filters.psc_codes` or `filters.assistance_listings` on `usaspending_search_awards` or on the three spending analytics tools — was dropped and the call answered without it; it now fails as `assistance_listings_type_mismatch` or `psc_codes_type_mismatch` ([#74](https://github.com/cyanheads/usaspending-mcp-server/issues/74), [#77](https://github.com/cyanheads/usaspending-mcp-server/issues/77)).
