# 0.4.1 — 2026-07-27

## Added

- **`USASPENDING_RETRY_BUDGET_MS`** env var — a wall-clock budget spanning every retry attempt of one request, so a per-attempt timeout is no longer re-paid on each retry. Defaults to 1.5x `USASPENDING_TIMEOUT_MS`. ([#52](https://github.com/cyanheads/usaspending-mcp-server/issues/52))
- **`formatCurrency()`** in `src/mcp-server/tools/definitions/formatting.ts` — shared currency formatter that places a negative sign outside the `$` (`-$264,436.97`, not `$-264,436.97`); every monetary `format()` site on the server now routes through it.
- **`resolveHasNext()` unit tests** (`tests/tools/pagination.test.ts`) — direct coverage of its three-boundary contract, previously exercised only incidentally through its two consumer tools.

## Changed

- **`USASpendingService`'s retry loop runs under one shared deadline** — `get()` and `post()` now route through a single `request()` primitive; an `AbortController` fires at the budget and composes with the caller's own abort signal. Deadline expiry from either propagation path (an abort mid-fetch, an abort mid-backoff) normalizes to one `Timeout` naming the exhausted budget instead of two incoherent raw errors. ([#52](https://github.com/cyanheads/usaspending-mcp-server/issues/52))
- **Nine paginated tools' `hasNext` reads verified against the live API** — `usaspending_disaster_spending`, `usaspending_get_agency` (sub-agency list), `usaspending_get_award_federal_accounts`, `usaspending_get_award_subawards`, `usaspending_get_award_transactions`, `usaspending_get_federal_account_breakdown`, `usaspending_search_federal_accounts`, `usaspending_search_recipients`, and `usaspending_spending_by_category` each carry a call-site comment recording the verified verdict and the depth it was checked to. All nine report `hasNext` truthfully at every boundary tested; no pagination guard was added to any of them. ([#54](https://github.com/cyanheads/usaspending-mcp-server/issues/54))
- **`resolveHasNext()`'s doc comment narrowed** — previously said "several" USAspending endpoints under-report `hasNext`; exactly one, `search/spending_by_award/`, is confirmed to. The comment now also states where the helper should and should not be applied.
- **`usaspending_get_idv_awards`'s guard comment corrected** — no longer claims a stale `hasNext` was observed on `idvs/awards/`. States what was verified (every constructible boundary, across IDVs with 6 and 16 children), what wasn't (the deep-offset regime, unreachable on that endpoint), and the guard's cost: a wrong `has_next: true` and an extra round trip on an exactly-full final page.
- **`usaspending_autocomplete_filters` README and design-doc examples corrected** — the NAICS example `"cybersecurity"` (0 upstream matches) is replaced with `"software"`; both docs now note that the `naics` lookup matches official NAICS title text, not colloquial industry language, and that `"aircraft maintenance"` resolves under `psc` rather than `naics`. ([#55](https://github.com/cyanheads/usaspending-mcp-server/issues/55))

## Fixed

- **`usaspending_disaster_spending` discloses a saturated recipient total as a ceiling rather than a count** — `disaster/recipient/spending/` reports exactly 10,000 once its reachable result set saturates (verified: a single DEF code reports an honest 3,045, while broader filters land on exactly 10,000 with the last page full and the page after it empty). The recipient dimension now emits `truncated`/`shown`/`cap`/`notice` enrichment fields when the reported total lands on that ceiling. ([#54](https://github.com/cyanheads/usaspending-mcp-server/issues/54))
- **`usaspending_search_awards`'s `upstream_messages` enrichment trailer no longer runs into the following entry** — the rendered bullet list now closes with a blank line so the next trailer entry (`applied_keyword` and similar) lands on its own line instead of reading as a lazy continuation of the last bullet under a strict markdown renderer.
- **Negative dollar amounts render with the sign outside the currency symbol** — `-$264,436.97`, not `$-264,436.97` — across every tool's `format()` output. Negative amounts are ordinary in this data: deobligations, downward contract modifications, and negative award-type columns in `usaspending_spending_over_time` all report reductions as negative values.
