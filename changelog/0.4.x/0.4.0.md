# 0.4.0 — 2026-07-27

## Changed

- **Breaking: `usaspending_autocomplete` renamed to `usaspending_autocomplete_filters`** — the old name is gone, not aliased. `tools/list` advertises only the new name; calling `usaspending_autocomplete` returns a tool-not-found error. Inputs, outputs, errors, and runtime behavior are unchanged. Update any client that calls the tool by name. ([#43](https://github.com/cyanheads/usaspending-mcp-server/issues/43))
- **`usaspending_spending_by_geography` gains a client-side `limit` (1–500, default 50)** — the upstream endpoint is not paginated and a nationwide county query matches 3,000+ areas (~650 KB uncapped). Areas are now ranked by `aggregated_amount` descending and sliced; a new `total_areas_available` output field reports the pre-slice match count, and the truncation disclosure names the withheld count plus the obligation amount of the lowest-ranked area shown. ([#48](https://github.com/cyanheads/usaspending-mcp-server/issues/48))
- **`usaspending_autocomplete_filters`'s recipient truncation guidance now states the bucket order** — the upstream `autocomplete/recipient/` endpoint fills name matches before UEI/DUNS matches, so once the name bucket saturates a page, raising `limit` cannot reach the identifier matches behind it. The guidance no longer suggests raising `limit` for that case and instead points at passing the identifier itself as `search_text`. ([#56](https://github.com/cyanheads/usaspending-mcp-server/issues/56))

## Fixed

- **`usaspending_autocomplete_filters`'s recipient lookup no longer returns up to 3x the requested `limit`** — `autocomplete/recipient/` applies `limit` per match bucket (name, UEI, DUNS) and unions them; results are now sliced to `input.limit` before returning, so `shown`/`cap` agree and the declared 1–500 range holds. ([#47](https://github.com/cyanheads/usaspending-mcp-server/issues/47))
- **`usaspending_spending_by_geography` no longer 500s when `filters` is omitted** — the tool was sending a bare `filters: {}`, which the endpoint answers with an HTTP 500 Django error page. A caller supplying no filters now gets `award_type_codes` defaulted to the complete 33-code accepted set (contracts, IDVs, grants, direct payments, loans, insurance, other assistance, and unspecified) rather than contracts-only, since a contracts-only default would have undercounted an unfiltered nationwide query by roughly 85%. The substitution is disclosed via a new `applied_award_type_default` enrichment field. ([#53](https://github.com/cyanheads/usaspending-mcp-server/issues/53))
- **`usaspending_get_award`'s `potential_end_date` no longer carries a time component** — upstream returns it as `"YYYY-MM-DD HH:MM:SS"` while `start_date`/`end_date` are plain dates; the time is always midnight, so it's now truncated to `YYYY-MM-DD` at assignment. All three `period_of_performance` date fields now state the format in their `.describe()`. ([#51](https://github.com/cyanheads/usaspending-mcp-server/issues/51))
