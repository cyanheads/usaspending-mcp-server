# 0.4.4 — 2026-09-25

## Changed

- **`usaspending_search_awards` `sort` follows the award type group** ([#60](https://github.com/cyanheads/usaspending-mcp-server/issues/60)). Loans sort by `Loan Value` (default), `Subsidy Cost`, `Issued Date`, `Recipient Name`, or `Awarding Agency`; other groups default to `Award Amount`, and IDVs have no `End Date`. Any other pairing fails as `unsupported_sort` before the request, listing the group's sorts.
- **Loan rows carry `loan_value`, `subsidy_cost`, and `issued_date`** on both `structuredContent` and the text output ([#60](https://github.com/cyanheads/usaspending-mcp-server/issues/60)).
- **`usaspending_search_awards` `assistance_listings`** filters by Assistance Listing (CFDA) number (`NN.NNN`, e.g. `93.866`, `11.67A`), sent as `program_numbers` and echoed as `applied_assistance_listings` ([#61](https://github.com/cyanheads/usaspending-mcp-server/issues/61)). Paired with contract or IDV codes, including the contract default, it fails as `assistance_listings_type_mismatch`.
- **`award_type_codes` descriptions list the full group partition** — IDV sub-codes, `F001`–`F010`, and the other-assistance group `09`/`11`/`-1`; an empty flat `award_type_codes` now fails schema validation ([#60](https://github.com/cyanheads/usaspending-mcp-server/issues/60)).
- **`usaspending_autocomplete_filters` `cfda` descriptions** point at `usaspending_search_awards` `assistance_listings` ([#61](https://github.com/cyanheads/usaspending-mcp-server/issues/61)).
- **`usaspending_disaster_spending` returns `totals`** — upstream's `obligation`, `outlay`, `total_budgetary_resources` or `award_count` for the whole result set on the agency, cfda, and recipient dimensions — plus per-row `total_budgetary_resources` on the agency dimension under `spending_type: total` ([#63](https://github.com/cyanheads/usaspending-mcp-server/issues/63)). Absent members stay absent; nothing is summed from the page.
- **Every date input advertises a `YYYY-MM-DD` pattern** on `usaspending_search_awards` and the three `usaspending_spending_*` tools, so a malformed date fails argument validation before any request ([#58](https://github.com/cyanheads/usaspending-mcp-server/issues/58)). Unpadded month and day are accepted and padded before sending; `""` still means no date.
- **The three `usaspending_spending_*` tools declare `date_before_earliest`** and reject a start before 2007-10-01 before the request, as `usaspending_search_awards` does.
- **Dev dependencies:** `@socketsecurity/bun-security-scanner` `^1.1.2` → `^1.1.3`, `@types/node` `^26.6.1` → `^26.6.2`.

## Fixed

- **Upstream timeouts and outages carry the tool contract on the wire** ([#57](https://github.com/cyanheads/usaspending-mcp-server/issues/57)). Every `Timeout` (budget expiry, exhausted per-attempt timeouts, a 504) is tagged `api_timeout` and every `ServiceUnavailable` (5xx, network, HTML or invalid-JSON body) `api_unavailable`, each with `retryable` and the calling tool's recovery hint.
- **`usaspending_disaster_spending`'s `api_timeout` recovery names a lever per dimension** — overview points at a later retry or the agency breakdown instead of narrowing it cannot apply, and geography drops `limit` ([#57](https://github.com/cyanheads/usaspending-mcp-server/issues/57)).
- **A 4xx error message quotes upstream's `detail`** (or `message`, when there is no `detail`), capped at 500 characters: `USAspending rejected <operation> (HTTP <status>): <detail>` ([#58](https://github.com/cyanheads/usaspending-mcp-server/issues/58)). Code and `data.status` are kept.
- **A US-style start date on `usaspending_search_awards` no longer fails as `date_before_earliest`** — the pattern rejects it by field name, and the floor check compares padded dates ([#58](https://github.com/cyanheads/usaspending-mcp-server/issues/58)).
- **A lone start or end date is applied, not dropped** ([#62](https://github.com/cyanheads/usaspending-mcp-server/issues/62)). A lone start runs through today (UTC), a lone end from 2007-10-01; `applied_time_period_*` echoes the range sent and a notice names the filled field. On `usaspending_spending_by_geography` a lone date no longer triggers the all-award-types default.
- **An inverted date range fails as `date_range_inverted` before any request**, naming both fields ([#64](https://github.com/cyanheads/usaspending-mcp-server/issues/64)). It had surfaced as `api_unavailable` from the analytics endpoints and been ignored by award search.
- **`usaspending_disaster_spending` recipient rows carry one usable `id`** — the recipient-level `-R` entry when upstream sends several, else the first — instead of a comma-joined string ([#65](https://github.com/cyanheads/usaspending-mcp-server/issues/65)).
- **`usaspending_disaster_spending` `spending_type` describes what upstream honors** — only the agency dimension varies with it.
