# 0.3.2 — 2026-07-27

## Fixed

- **`usaspending_search_awards`'s `has_next` no longer goes false at a 10,000-result offset while a full page of results remains** — continuation now falls back to page fullness (`results.length >= limit`) when the upstream flag under-reports, via a new `resolveHasNext()` helper shared with `usaspending_get_idv_awards`. The `page` and cursor-field descriptions, the `pagination_limit_exceeded` recovery hint, and the truncation guidance now state the 10,000-result window where the keyset cursor stops being emitted; `format()` distinguishes a page withholding the cursor because of that window from an ordinary final page, and no longer directs a caller past the 50,000-result page-number cap. ([#44](https://github.com/cyanheads/usaspending-mcp-server/issues/44))
- **`usaspending_spending_over_time` no longer drops direct-payment obligations** — the handler read a nonexistent `Direct Payment_Obligations` key; the endpoint returns `Direct_Obligations`. A new `idvs` output field (and `format()` table column) maps the previously-unmodeled `Idv_Obligations`. ([#45](https://github.com/cyanheads/usaspending-mcp-server/issues/45))
- **`usaspending_get_idv_awards` reads pagination from `page_metadata`, not the response's top level** — `hasNext`, `hasPrevious`, and `page` all resolved to `undefined` under the old flat read, pinning `has_previous` to `false` on every call and discarding the real upstream `hasNext`. `format()` now renders `Has previous` alongside the existing fields. ([#46](https://github.com/cyanheads/usaspending-mcp-server/issues/46))
- **`usaspending_search_awards`'s `enrichmentTrailer.upstream_messages` label now renders in `content[]`** — the framework's trailer renderer treats a configured `render` function as a full escape hatch and never consults a sibling `label`, so the API-notices heading now emits from inside `render` instead. ([#50](https://github.com/cyanheads/usaspending-mcp-server/issues/50))
