# 0.3.1 — 2026-07-27

## Added

- **`api_timeout`** error contract entry on all 18 tools — `@cyanheads/mcp-ts-core` 0.10.17 restored `Timeout` (-32004) classification for fetch timeouts, previously misclassified as `ServiceUnavailable`. The tool definitions now declare the contract the handlers already throw into, each with a recovery hint scoped to what that endpoint can narrow (a smaller `limit`, a shorter `time_period`, fewer filters).
- **`scripts/build-changelog.ts` rejects leaked control markup** in a per-version entry body — a whole line matching a bare angle-bracket tag (e.g. `</content>`, `<invoke name="...">`) hard-fails the rollup build, naming the file and line. Frontmatter was already validated; the body was not, and `changelog/0.2.x/0.2.9.md` shipped two such lines into the published npm tarball and GitHub release before this guard existed. New `tests/scripts/build-changelog.test.ts` covers the rejection and confirms inline angle brackets (`` post<T>() ``, `["<code>"]`) and standalone renderable HTML (`<details>`) stay accepted. ([#42](https://github.com/cyanheads/usaspending-mcp-server/issues/42))

## Fixed

- **`usaspending_get_award_transactions` and `usaspending_get_award_subawards` drop their unreachable `award_not_found` contract** — both endpoints answer an unknown `award_id` with HTTP 200 and zero rows, which the handlers already disclose via an enrichment notice; the declared reason advertised a failure mode no input could produce. ([#49](https://github.com/cyanheads/usaspending-mcp-server/issues/49))
- **`USASpendingService` reads the framework's canonical `error.data.status`** field instead of the legacy `statusCode` alias, and threads `expectedStatuses` through `fetchWithTimeout` for the entity-lookup and agency sub-resource calls, so a routine upstream miss logs at `debug` instead of `error`.

## Changed

- **`@cyanheads/mcp-ts-core`** `^0.10.14` → `^0.11.0`, spanning 0.10.15–0.11.0: TypeScript 7, `withRetry` honoring `Retry-After`, configurable logger rate limiting, and `.mcpb` bundles stripped of platform-specific native bindings — plus the template, script, and skill sync that came with it (`CLAUDE.md`, `scripts/devcheck.ts`, `scripts/check-dependency-specifiers.ts`, `scripts/clean-mcpb.ts`, `scripts/lint-packaging.ts`, and the `api-canvas`, `api-config`, `api-utils`, `field-test`, `git-wrapup`, `orchestrations`, `tool-defs-analysis` skills).
- **`.gitignore`** anchors `data/` to `/data/` — the unanchored pattern also matched `src/data/` and other nested `data/` directories.
- **`Dockerfile`** adds `--omit=dev --ignore-scripts` to the OTEL `bun add` in the production stage, so it no longer re-resolves the dev toolchain back into the final image.
- **`devcheck.config.json`** drops `typescript` from the `outdated` allowlist now that the server tracks the 7.x line.
